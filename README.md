# Бадучай — демонстрационный прототип чайного каталога

Отдельный демонстрационный сайт: быстрый чайный каталог со сборкой большого заказа
на компьютере и телефоне. Данные — снимок публичного каталога
[baduchai.ru](https://baduchai.ru/).

> **Это демонстрация.** Настоящие заказы не принимаются и не оплачиваются,
> с магазином прототип не связан. Персональные данные из формы оформления
> никуда не отправляются и нигде не сохраняются.

## Запуск

```bash
npm install
npm run dev       # разработка, http://localhost:5173
npm run build     # сборка в dist/ (tsc -b + vite build)
npm run preview   # просмотр собранной версии
```

## Проверки

```bash
npm test            # 77 модульных тестов (vitest)
npm run build       # сборка обязательна перед двумя следующими командами
npm run qa:browser  # 36 браузерных сценариев (playwright) + скриншоты в qa/
npm run perf        # замер скорости, отчёт в qa/perf-report.json
```

## Обновление снимка каталога

```bash
npm run catalog:fetch
```

Скрипт `tools/fetch-catalog.mjs` читает **публичный** WooCommerce Store API
(`/wp-json/wc/store/v1`), нормализует данные и складывает их в
`src/data/catalog.json`, а превью-изображения — в `public/img/`. Только чтение:
корзина и заказы магазина не затрагиваются, cookies и админские данные не
используются. Темп запросов щадящий (один запрос списка + по одному на картинку
с паузой), параллельного обхода нет. `robots.txt` магазина на дату снимка
разрешает чтение (`Disallow:` пустой).

## Что умеет прототип

**Каталог** — поиск по названию, артикулу, китайскому названию и псевдонимам;
фильтр по категории; фасовка, цена и наличие в карточке; короткое описание и фото
без перехода на другую страницу; ввод количества и кнопки ±. Количество всегда
означает подписанную единицу продажи (блин 357 г, мешочек 100 г и т. п.).

**Корзина** — редактирование и удаление позиций, число упаковок, общий вес и
сумма, сохранение между перезагрузками, отдельный вид для телефона. Ничего не
добавляется автоматически. Скидки и доставка в сумму не входят: их условия
магазин согласует лично.

**Вставка списка текстом** — детерминированный разбор без внешних сервисов.
Понимает нумерацию, тире/двоеточие/`x`/табуляцию, «шт.», артикулы, регистр и
лишние пробелы. До изменения корзины показывается предпросмотр: исходная строка,
найденный товар и фасовка, количество, ошибки. Неоднозначные строки требуют
выбора, дубликаты объединяются явно, некорректные количества отклоняются.
Покупатель отдельно выбирает «заменить корзину» или «добавить к корзине».

**Excel** — скачивание прайса-шаблона `.xlsx` (артикул, название, фасовка, цена,
валюта, наличие, количество) и импорт заполненного файла с тем же предпросмотром
и теми же проверками. Артикулы хранятся как текст; выгрузка не содержит формул,
а формулы во входящем файле читаются как значения и не выполняются.

**Повтор закупки** — сохранение набора на устройстве и загрузка снова.
Восстановление идёт по идентификаторам товаров, цены и вес пересчитываются по
текущему снимку, об исчезнувших и недоступных товарах сообщается явно.

**Демонстрационное оформление** — почта, получатель, адрес, проверка обязательных
полей, сводка заказа и экран завершения с явной пометкой, что настоящий заказ не
создан. Есть кнопка подстановки тестовых данных.

## Устройство

Лёгкий фронтенд без сервера: Vite + React + TypeScript, снимок каталога в виде
JSON. Поиск, разбор списков и пересчёт корзины выполняются локально в браузере,
каталог не запрашивается у магазина при каждом открытии, изображения
оптимизированы в webp и грузятся по мере прокрутки.

```
src/lib/       данные и логика: types, text, match, qty, parseOrder,
               totals, xlsx, importSheet, storage
src/state/     корзина и сохранённые наборы
src/components/интерфейс
src/data/      снимок каталога
src/test/      модульные тесты
tools/         сборщик снимка, браузерная проверка, замер скорости
docs/          план подключения настоящего оформления WooCommerce
```

Чтения `.xlsx` и записи сделаны своим минимальным кодом поверх `fflate` —
это убирает зависимость от офисных библиотек и даёт полный контроль над тем,
чтобы в файлах не появлялось исполняемых формул. В проекте `npm audit` — 0
уязвимостей.

## Ограничения снимка

- Цены, наличие и состав зафиксированы на дату снимка, она показана в интерфейсе.
- У части товаров фасовка в магазине не опубликована. Вес не додумывается:
  такие позиции помечаются, а общий вес показывается как нижняя граница.
- Оптовые цены, скидки, остатки на складе и отзывы магазин не публикует,
  поэтому прототип их не показывает и не выдумывает.
- В артикулах магазина встречается и латинская `O`, и кириллическая `О`
  (см. `meta.sku_collisions`). Такие артикулы дают несколько кандидатов, и
  прототип просит выбрать, а не угадывает.
