# Бадучай — демонстрационный прототип каталога

Отдельный демонстрационный сайт: быстрый каталог со сборкой большого заказа
на компьютере и телефоне. Данные — снимок публичного каталога
[baduchai.ru](https://baduchai.ru/): **1310 товаров, 26 рубрик**, включая чай,
чайники, нефрит, чашки, курильницы, сандал и остальные разделы магазина.

> **Это демонстрация.** Настоящие заказы не принимаются и не оплачиваются,
> с магазином прототип не связан. Персональные данные из формы оформления
> никуда не отправляются и нигде не сохраняются.

## Запуск

```bash
npm install
npm run dev       # разработка, http://localhost:5173
npm run build     # сборка в dist/ (tsc -b + vite build)
npm run preview   # просмотр собранной версии
```

## Проверки

```bash
npm test            # 104 модульных теста (vitest)
npm run build       # сборка обязательна перед следующими командами
npm run qa:browser  # 48 браузерных сценариев (playwright) + скриншоты в qa/
npm run qa:widths   # вёрстка на 11 ширинах от 320 до 1440 px
npm run perf        # замер скорости, отчёт в qa/perf-report.json
npm run qa:all      # всё перечисленное подряд
```

## Обновление снимка каталога

```bash
npm run catalog:fetch
```

Скрипт `tools/fetch-catalog.mjs` читает **публичный** WooCommerce Store API
(`/wp-json/wc/store/v1`), нормализует данные и складывает их в
`public/catalog.json`, а превью-изображения — в `public/img/`. Только чтение:
корзина и заказы магазина не затрагиваются, cookies и админские данные не
используются. Темп запросов щадящий (постраничный список по 100 товаров с паузой
800 мс + по одному запросу на картинку с паузой 120 мс), параллельного обхода нет,
уже скачанные изображения не перезапрашиваются. `robots.txt` магазина на дату снимка
разрешает чтение (`Disallow:` пустой).

## Что умеет прототип

**Каталог** — поиск по названию, артикулу, китайскому названию и псевдонимам;
фильтр по рубрикам, повторяющий меню магазина: рубрики верхнего уровня, под ними
подрубрики выбранной, и третий уровень у «Улун». Выбор родительской рубрики
показывает и товары вложенных. Рубрики всегда переносятся по строкам; если на
узком экране они не помещаются в два ряда, появляется кнопка «Показать все
рубрики» — горизонтальной прокрутки, в которой ряд выглядел обрезанным, нет. Фасовка, цена и наличие в карточке; короткое
описание и фото без перехода на другую страницу; ввод количества и кнопки ±.
Количество всегда означает подписанную единицу продажи (блин 357 г, мешочек
100 г, для предметов — штука).

**Корзина** — редактирование и удаление позиций, число упаковок, общий вес и
сумма, сохранение между перезагрузками, отдельный вид для телефона. Ничего не
добавляется автоматически. Скидки и доставка в сумму не входят: их условия
магазин согласует лично.

**Вставка списка текстом** — детерминированный разбор без внешних сервисов.
Понимает нумерацию, тире/двоеточие/`x`/табуляцию, «шт.», артикулы, регистр и
лишние пробелы. До изменения корзины показывается предпросмотр: исходная строка,
найденный товар и фасовка, количество, ошибки. Неоднозначные строки требуют
выбора, дубликаты объединяются явно, некорректные количества отклоняются.
Покупатель отдельно выбирает «заменить корзину» или «добавить к корзине».

**Excel** — скачивание прайса-шаблона `.xlsx` (артикул, название, фасовка, цена,
валюта, наличие, количество) и импорт заполненного файла с тем же предпросмотром
и теми же проверками. Артикулы хранятся как текст; выгрузка не содержит формул,
а формулы во входящем файле читаются как значения и не выполняются.

**Повтор закупки** — сохранение набора на устройстве и загрузка снова. Название
придумывать не нужно: подпись складывается из даты и состава, а рядом можно
оставить необязательный комментарий. Восстановление идёт по идентификаторам
товаров, цены и вес пересчитываются по текущему снимку, об исчезнувших и
недоступных товарах сообщается явно.

**Демонстрационное оформление** — почта, получатель, адрес, проверка обязательных
полей, сводка заказа и экран завершения с явной пометкой, что настоящий заказ не
создан. Есть кнопка подстановки тестовых данных.

## Оформление

Прототип намеренно повторяет фирменный вид baduchai.ru, чтобы владелец
сравнивал не картинки, а скорость работы: шрифты Neucha и Inconsolata,
фоновая плашка, логотип, меню-сетка с тонкими разделителями, безрамочные
карточки товара и та же серая палитра. Значения сняты с сайта скриптом
`tools/study-original.mjs` (только чтение публичных страниц).

Шрифты и фон лежат локально в `src/assets` и проходят через сборщик — внешних
запросов к Google Fonts нет, поэтому текст виден с первого кадра.

## Устройство

Лёгкий фронтенд без сервера: Vite + React + TypeScript. Снимок каталога лежит
отдельным файлом `public/catalog.json` и подгружается при старте — оболочка
появляется сразу, а файл кешируется браузером. Поиск, разбор списков и пересчёт
корзины выполняются локально, каталог не запрашивается у магазина при каждом
открытии. Изображения берутся из опубликованного магазином варианта не мельче 700 px и
пересобираются в webp 560×560 (в среднем 22 КБ) — раньше превью 300×300
растягивалось и выглядело мылом. Грузятся по мере прокрутки; карточки
отрисовываются порциями по 48 с подгрузкой при прокрутке.

```
src/lib/       данные и логика: types, text, match, qty, parseOrder,
               totals, xlsx, importSheet, storage
               categories (дерево рубрик)
src/state/     корзина и сохранённые наборы
src/components/интерфейс
public/        снимок каталога catalog.json и изображения img/
src/test/      модульные тесты
tools/         сборщик снимка, браузерная проверка, замер скорости
docs/          план подключения настоящего оформления WooCommerce
```

Чтения `.xlsx` и записи сделаны своим минимальным кодом поверх `fflate` —
это убирает зависимость от офисных библиотек и даёт полный контроль над тем,
чтобы в файлах не появлялось исполняемых формул. В проекте `npm audit` — 0
уязвимостей.

## Ограничения снимка

- Цены, наличие и состав зафиксированы на дату снимка, она показана в интерфейсе.
- Вес считается только для чая — для чайника или браслета он не является единицей
  продажи. У 3 чайных позиций магазин вес не
  публикует; он не додумывается, эти позиции названы поимённо, а общий вес
  показан как нижняя граница.
- У товара A-517 в магазине пустое название — вместо него показан артикул.
- В меню сайта есть раздел «КИНОВАРЬ», но в публичном API товаров с такой
  рубрикой нет, поэтому в снимке её тоже нет.
- Оптовые цены, скидки, остатки на складе и отзывы магазин не публикует,
  поэтому прототип их не показывает и не выдумывает.
- В артикулах магазина встречается и латинская `O`, и кириллическая `О`
  (см. `meta.sku_collisions`). Такие артикулы дают несколько кандидатов, и
  прототип просит выбрать, а не угадывает.
